# 课程河流 (Curriculum Roadmap)

AI 驱动的课程规划与管理系统，帮助教育工作者自动化课程单元数据的创建与管理。支持多用户账号隔离、云端数据同步与多种可视化视图。

---

## 技术栈


| 层级  | 技术                                                                |
| --- | ----------------------------------------------------------------- |
| 前端  | React 18 + TypeScript、Vite、Tailwind CSS + shadcn/ui、自定义 i18n（中/英） |
| 后端  | Node.js + Express.js                                              |
| 数据  | PostgreSQL（如 Zeabur Neon）                                         |
| 其他  | pdfjs-dist（PDF 解析）、HTML5 Canvas（概念网络图）                            |

## 核心功能

- **课程管理**：创建/编辑/删除课程，分类与双语支持，协和色系课程色、按年级周课时（含 0.5 节阶梯）、开设年级与教材版本；年级配置支持**学段 + 年级**两级结构（`grade_config.segments`）。
- **单元管理**：手动或 AI 生成单元，Excel 批量导入，拖拽排序，单元与关键概念关联。
- **可视化**：整体视图（课程河流）、单元视图、概念视图（力导向图）；顶栏统一视图切换，可按**学段**筛选整体视图（与全校年级配置联动）。
- **AI**：单元生成（DeepSeek/GLM/Kimi）、教材上传（TXT/PDF）、基于课程上下文的聊天助手。
- **数据**：云端同步（课程、学期数据、关键概念），本地缓存与离线回退，JSON 导入/导出，多用户数据隔离。
- **课堂助手**：班级内个人/小组积分、分组方案与小组管理；可选云端同步（与后台班级、学生数据联动）。

## 平台模块一览

以下概括各主要入口的职责边界，便于产品迭代与权限设计对齐。

| 模块 | 说明 |
| --- | --- |
| **课程河流 / 课程管理** | 全校课程结构、单元与关键概念、多视图浏览（整体/单元/概念）；与年级学段配置联动。 |
| **课堂助手** | 课中执行层：班级积分、分组与小组管理；可与班级、学生云端数据联动。 |
| **后台管理** | 账号与角色、班级与学生主数据、评价报告模板发布、部分全校设置（如年级配置）等治理入口。 |
| **学生画像** | 面向单个学生的**长期发展视图**（见下节）；聚合多类数据与可视化，并可扩展分析或 AI 建议。**不等于**单次学业报告界面本身。 |
| **学业报告（学生画像子模块）** | 按学年/学期、模板的学科评价与班主任评语等；为画像提供**学科侧评估数据**的来源之一。 |
| **AI 助手** | 贯穿备课、单元生成与课程上下文的对话与生成能力。 |

## 学生画像与学业报告的定位

**学生画像**在概念上**高于**学业报告：它描述的是学生在校**长期发展**的特质集合，强调时间维度上的变化与综合视图，并可做可视化呈现。画像可涵盖但不限于：

- 学业报告所沉淀的**学科评价**数据（仅作为来源之一）；
- **兴趣特长**等发展性描述或结构化记录；
- **通用学习能力**（如学习策略、认知习惯等框架）；
- **社会情感能力**（如协作、自我管理等 SEL 相关维度）；
- 类似「学生发展中心」的视角：长期成绩或等第趋势、能力发展曲线，并支持基于数据或 **AI** 的**发展建议**。

**学业报告**则是按学期、按模板的**学科维度评价 + 班主任评语**等表单化产出，主要服务教务评价流程；它**为画像补充学科侧证据**，但**不应与「学生画像」整体划等号**。产品演进上，画像页会以多标签/多框架方式扩展，学业报告作为其中一块（例如「学业报告」标签）持续迭代。

## 项目结构（Monorepo）

```
├── apps/
│   ├── web/          # 前端 (React + Vite)
│   └── api/          # 后端 (Express)，并托管前端静态资源
├── libs/
│   └── shared/       # 共享类型与常量
├── package.json      # 根 workspace 脚本
└── README.md
```

- **前端**：`apps/web`（组件、contexts、lib、类型定义）。
- **后端**：`apps/api`（路由、数据库配置、静态资源来自构建后的 `apps/web`）。
- **共享**：`libs/shared` 供前后端共用。

## 数据流简述

- **写入**：用户操作 → 先写本地缓存 → 若启用云端则调 API → 后端按 `X-User-Id` 识别用户并写入 PostgreSQL。
- **读取**：优先从云端加载 → 成功则更新本地缓存 → 失败则回退本地。
- **隔离与共享**：本地缓存键通过 `getUserStorageKey()` 加用户 ID 前缀；云端按业务域区分为“权限隔离数据”（如用户设置）与“全校共享数据”（如班级、学生、课程模板与报告等）。

## 本地开发与构建

### 环境变量

- **仅前端 + localStorage（默认轻便开发）**：`apps/web/.env` 中 `VITE_USE_CLOUD_STORAGE=false`。无需启动 API/数据库；登录可用预设账号（见登录页提示）。班级与学生数据在本浏览器 `localStorage`，**不自动迁移**到服务器。
- **联调真实后端**：`VITE_USE_CLOUD_STORAGE=true`，并设置 `VITE_API_URL`（例如 `http://127.0.0.1:8080/api`），同时启动 `npm run dev` 中的 API 或使用 `npm run dev:api`。
- **后端**：复制 `apps/api/.env.example` 为 `apps/api/.env`，配置 `DATABASE_URL` 与 `JWT_SECRET`（云端登录依赖 JWT）。

### 本地 PostgreSQL（Docker）

```bash
npm run db:up   # docker compose up -d
npm run db:init # 执行 apps/api/src/config/init.sql（无需本机 psql）
```

PostgreSQL 结构以 `apps/api/src/config/init.sql` 为唯一来源；测试阶段改表直接改该文件后执行 `npm run db:init`，或 `docker compose down -v && npm run db:up && npm run db:init` 清空重建。

### 常用命令

```bash
# 安装依赖
npm install

# 开发（先构建 shared，再同时起 API:8080 + Vite 前端）
npm run dev

# 仅前端
npm run dev:web

# 仅后端
npm run dev:api

# 构建并运行（先构建 shared → web → 复制到 api/public → 构建 api）
npm run build
npm start
```

## 版本与状态

- **当前版本**：1.0.9（`V109` 已合入 `main`：学业报告配置与教师端填写体验、组织/岗位与数据层整理）  
- **上一里程碑**：1.0.8 课程与年级体系、课程河流视图迭代已收束并合入 `main`。  
- **状态**：主线 `main` 含本版本学业报告三步配置、考试学科与教师画像填写优化等；生产部署前请执行 `npm run build` 与联调回归。  
- **历史**：
  - **v1.0.0** 项目初始可用版本，完成“课程河流”主流程闭环：课程建档、学期与单元管理、基础可视化浏览。该版本重点是先把教学设计数据结构跑通，建立后续扩展的最小骨架。
  - **v1.0.1** 增强课程生产效率，加入跨设备数据同步、AI 生成单元与导入能力，明显降低从“课程想法”到“结构化单元”的录入成本。也是从单机工具向多人协作系统过渡的关键一步。
  - **v1.0.2** 上线全局 AI 能力，将 AI 从单点工具提升为应用级助手：在更多页面可直接调用，围绕课程上下文持续对话与生成，提升备课与调整的连续性。
  - **v1.0.3** 引入后台管理体系，补齐账号、权限与数据治理入口，为学校级部署做准备。该阶段开始明确“系统管理员/管理员/教师”边界，减少配置分散导致的维护成本。
  - **v1.0.4** 新增课堂助手模块，支持分组方案、小组管理与积分事件记录，把课程规划能力延伸到课堂执行层。实现了“课前规划 + 课中管理”联动，提升日常教学可操作性。
  - **v1.0.5** 重构主界面 HUB 交互：固定网格布局、拖拽编辑、响应式与细节体验优化，解决高频入口切换与信息密度问题。该版本主要目标是“让常用操作更快、页面结构更稳”。
  - **v1.0.6** 学生登录账号（学号开通）、学生画像与学生端只读权限边界；班级/后台等相关 API 与 Docker 本地库等配套调整。
  - **v1.0.7** 学业报告模板驱动（管理员配置学年/学期/学科目标维度并发布，教师按模板填写，学生仅查看本人）；新增后台“数据库”只读可视化（仅 `system-admin`：表清单、行数统计、分页浏览）；课程与学期数据改为全校共享并由权限控制读写（管理员可写、教师可读）；班级创建强制配置主负责老师（`homeroom`）并保持每班可识别负责人；完善本地联调链路与 API 地址兼容（`VITE_API_URL` 支持带或不带 `/api`）。**本阶段已合并至 `main` 并标记收束。**
  - **v1.0.8**（已合入 `main`）课程与年级体系增强：**全校 `grade_config`** 支持学段（`segments`）与年级（`items`），年级设置为先建学段再在学段内维护年级；**课程河流 / 后台课程管理** 共用顶栏中间视图切换——「整体视图」（全校）与各学段 Tab（按最低年级排序，整体在最右）、单元视图、概念视图分组展示，协和蓝（`primary`）为选中态；整体视图按 Tab 筛选年级行与课程列，课程实体仍跨学段一条配置。课程色与周课时等逻辑部分沉淀至 `@repo/shared`；API `settings` 的 `grade-config` 读写与 JSON 归一化对齐前端。后台嵌入顶栏视图标签水平居中；Tab 分组外壳无内边距以避免选中态双层圆角缝隙。
  - **v1.0.9**（已合入 `main`）**学业报告与评价**：后台学年维度预设支持「学科目标 → 考试学科 → 新建学业报告」流程；考试学科可按学期/学段保存纳入列表（允许零门）、支持**分学科保存**考试规则且持久化时合并草稿与已存配置避免覆盖未编辑学科；分数等第默认档与 `@repo/shared` 中 `REPORT_SCORE_LETTER_GRADES` / `defaultReportScoreGradeMinScores` 对齐（如 D 下限为 0）。**管理员预览与教师填写**：学科评价区将「评价维度、学习品质（兴趣/习惯/态度）、测评成绩」并入**同一张表**，末两行与课程目标行视觉区分；简化预览下移除学科卡片四角开关及冗余说明文案；「完成并关闭」与分步保存文案对齐。**组织与人员**：新增组织/结构相关后台能力、教职工导入与展示辅助（`staffingSubjectKey` 等共享逻辑）；API 侧 `init.sql` 收敛为单一基线并补充 staffing 相关保障（`ensureStaffingTables`），移除零散 migrate 片段文件。
