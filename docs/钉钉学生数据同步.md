# 钉钉家校通讯录 · 学生数据同步（v0.5.1）

面向 **SUIS Compass 后台 · 学生管理**：从钉钉 **行业通讯录 / 家校通讯录** 拉取组织架构与学生名单，写入本地 `students` / `student_enrollments`，替代或补充 Excel 手工导入，保证数据与钉钉侧一致。

> **安全**：Client Secret 等密钥**仅**放在 `apps/api/.env`（已 gitignore），勿写入 README、代码或聊天记录截图。若密钥曾泄露，请在[钉钉开发者后台](https://open-dev.dingtalk.com/)轮换 Client Secret。

## 2. 接口权限（上线前在开发者后台申请）

调用行业 / 家校通讯录读接口前，在应用 **权限管理** 中开通（名称以控制台为准）：

- **钉钉教育家校通讯录读权限**（`topapi/edu/user/list` 等）
- **行业通讯录** 相关读权限（部门列表、部门下人员等）
- 基础权限 `qyapi_base`（获取 accessToken，企业内部应用默认具备）

部分行业接口属于**特殊权限**，需填写申请说明，约 1 个工作日内审批。若调用返回 `AccessDenied` / 缺少 scope，按错误体中的 `requiredScopes` 在权限管理页搜索并申请。

参考：[添加接口调用权限](https://open.dingtalk.com/document/development/add-api-permission)

## 3. 鉴权：accessToken

**推荐（新版）** — 企业内部应用：

```http
POST https://api.dingtalk.com/v1.0/oauth2/accessToken
Content-Type: application/json

{
  "appKey": "<DINGTALK_CLIENT_ID>",
  "appSecret": "<DINGTALK_CLIENT_SECRET>"
}
```

响应：`accessToken`（有效期 **7200 秒**）、`expireIn`。服务端应**缓存** token，按过期时间刷新，避免频繁请求被限流。

文档：[获取企业内部应用的 accessToken](https://open.dingtalk.com/document/orgapp/obtain-the-access_token-of-an-internal-app)

**旧版（仍可用）** — 部分 `topapi/*` 示例使用 query 参数：

```http
GET https://oapi.dingtalk.com/gettoken?appkey=<CLIENT_ID>&appsecret=<CLIENT_SECRET>
```

后续行业接口统一在 URL 上携带 `access_token=<token>`（`oapi.dingtalk.com`）。

## 4. 核心 API 与调用顺序

### 4.1 获取部门列表（遍历组织树）

家校 / 行业通讯录为树形结构。从根部门 `dept_id = 1` 开始，递归拉取子部门，直到 `dept_type === 'class'`。

```http
POST https://oapi.dingtalk.com/topapi/industry/department/list?access_token=<token>
Content-Type: application/json

{
  "dept_id": 1,
  "cursor": 0,
  "size": 1000
}
```

| 响应字段 | 说明 |
|----------|------|
| `result.details[].dept_id` | 部门 ID |
| `result.details[].name` | 部门名称 |
| `result.details[].dept_type` | 学校场景：`campus` 校区、`period` 学段、`grade` 年级、`class` 班级 |
| `result.details[].feature` | JSON 字符串，含 `grade_level`、`start_year`、`class_level` 等扩展属性 |
| `result.has_more` / `next_cursor` | 分页 |

文档：[获取部门列表（行业通讯录）](https://open.dingtalk.com/document/development/obtains-a-list-of-industry-departments)

典型结构（classic 四层）：校区 → 学段 → 年级 → 班级。

### 4.2 获取班级学生列表（家校 2.0，推荐）

对每个 `dept_type = class` 的 `dept_id`：

```http
POST https://oapi.dingtalk.com/topapi/edu/user/list?access_token=<token>
Content-Type: application/json

{
  "class_id": 4242006,
  "role": "student",
  "page_no": 1,
  "page_size": 30
}
```

| 响应字段 | 说明 |
|----------|------|
| `result.details[].userid` | 钉钉用户 ID，建议作外部主键 |
| `result.details[].name` | 姓名 |
| `result.details[].class_id` | 班级 ID |
| `result.details[].feature` | JSON，常见 `student_no`（学号，班级未配置则可能缺失） |
| `result.details[].unionid` | 开放平台唯一标识（部分无手机号学生为空） |
| `result.has_more` | 是否还有下一页 |

`page_size` 取值 **1～30**，需分页直至 `has_more === false`。

文档：[获取人员列表（家校）](https://open.dingtalk.com/document/isvapp/obtains-a-list-of-home-school-user-identities)

### 4.3 备选：部门下人员列表（行业通用）

若家校 2.0 接口不可用，可对班级 `dept_id` 调用：

```http
POST https://oapi.dingtalk.com/topapi/industry/user/list?access_token=<token>
Content-Type: application/json

{
  "dept_id": 4242006,
  "role": "student",
  "cursor": 0,
  "size": 1000
}
```

文档：[获取部门下人员列表](https://open.dingtalk.com/document/orgapp/obtains-the-list-of-people-under-a-department)

## 5. 与本地数据模型映射（规划）

| 钉钉 | 本地表 / 字段 | 备注 |
|------|----------------|------|
| `userid` | `students.id` 或新增 `dingtalk_user_id` | v051 实现时二选一：直接作 id 或单独外键列 |
| `name` | `students.name` / `name_zh` | 按现有「中文名优先」规则 |
| `feature.student_no` | `students.student_number` | 学号 |
| `class_id` + 部门树 | `student_enrollments` + `classes` | 需将钉钉 `class` 部门映射到本系统 `classes.id` |
| 部门树 `grade` | `students.current_grade` | 可读 `feature.grade_level` |
| — | `students.gender` | 钉钉学生列表**不保证**返回性别；缺失时保留原值或默认策略 |

**同步策略（待实现）**：

1. **全量**：遍历部门树 → 拉取全部班级学生 → upsert `students` + 当前学年 `student_enrollments`。
2. **增量**：定时任务（建议 ≥ 15 分钟，配合 token 缓存）+ 后台「立即同步」按钮。
3. **冲突**：以钉钉为**主数据源**；本地 Excel 导入在 v051 后降为补充/应急，具体产品规则实现时再定。

## 7. 调试与排错

1. 先用 API Explorer（开发者后台）或 curl 验证 token 与单个 `class_id` 能否返回学生。
2. `errcode !== 0`：对照[全局错误码](https://open.dingtalk.com/document/orgapp-server/serverapi-error-codes)；常见为权限未开通、token 过期、dept_id 不属于家校通讯录。
3. 学号为空：检查钉钉班级是否开启学号字段。
4. 生产部署：在 `docs/上线注意事项.md` 的 P0 环境变量清单中补充 `DINGTALK_*`（Secret 走平台密钥管理，勿打进镜像）。

## 8. 班级名映射与确认式同步（v0.5.1）

### 8.1 钉钉 → 本地班名

| 钉钉示例 | 本地班名 | 规则 |
|----------|----------|------|
| 七年级1班 | S7A | 中学（7–12 年级）→ `S` + 年级 + 班别字母 |
| 八年级1班 | S8A | 1班=A，2班=B…5班=E，**6班=G**（跳过 F） |
| 三年级2班 | P3B | 小学（1–6 年级）→ `P` + 年级 + 班别字母 |
| 二年级6班 | P2G | 6 班班别字母为 **G**，不是 F |

**年级解析优先级**：钉钉 `feature.grade_level` 在**初中学段**常为相对值 1–3（对应七/八/九年级），与部门名称「七年级」等冲突。映射时**优先从 `gradeName` / 组织路径中的中文年级名解析**（如七年级→7→S7A），仅在无文字年级时才回退 `grade_level`。

代码：`apps/api/src/services/dingtalk/classNameMapping.ts`。本地 **当前学年** 须已存在对应班名（如 `S8A`），否则同步计划会标记「无法匹配」。

若历史同步已错配班级，系统管理员可调用 `POST /api/admin/dingtalk/sync/repair-classes`（需先刷新钉钉快照），按最新映射重算所有带 `dingtalk_user_id` 学生的学籍班级。

### 8.2 校区同步范围

默认仅同步 **合肥市包河区协和双语学校** 组织树下的班级与学生，**排除「选课测试」** 及其全部子节点。

可在 `apps/api/.env` 覆盖（逗号分隔多个名称）：

```env
DINGTALK_CAMPUS_INCLUDE=合肥市包河区协和双语学校
DINGTALK_CAMPUS_EXCLUDE=选课测试
```

刷新钉钉 API 预览后，界面会显示当前包含/排除的校区名称。

### 8.3 操作流程

1. 后台 → **数据库** → **钉钉 API** → **刷新**（只拉钉钉组织树 + 班级名单，**不写库、不调逐人详情**）
2. 点击 **同步学生数据** → 生成差异清单（新增 / 更新 / 删除），并展示 **钉钉去重人数**、**班级人数差异**
3. **逐项勾选** 后确认执行；删除默认不勾选。确认同步时复用已生成的计划，避免重复全库比对

**数据流**：钉钉 API → 服务端内存快照 + 浏览器 localStorage → `sync/plan` 差异 → `sync/apply` 写库（学号补齐在此步）。同一 userid 在多个钉钉班级出现时，比对时只计一次。

**班级对齐**：`classNameMapping` 将钉钉年级/班别映射为 `P/S + 年级 + 字母`；同步对话框中的「班级人数差异」按本地班汇总钉钉映射人数与学籍人数，便于发现某班人多/人少。

若历史数据班级错配，系统管理员可在刷新快照后调用 `POST /api/admin/dingtalk/sync/repair-classes` 批量重算学籍班级。

### 8.4 字段与限制

- **可同步**：userid、姓名、学号（班级已配置）、年级/入学年份（组织树推导）、学籍班级
- **学号自动生成**：钉钉未提供、**仅为班内序号（1–2 位）**或冲突时，按 **YYGCCSS** 规则生成（与系统登录名一致）  
  - **YY**：入学年两位（钉钉 `start_year`，否则当前学年起年）  
  - **G**：年级数字（1–12）  
  - **CC**：班序号（P2A→01，P2G→06，与班级映射一致）  
  - **SS**：班内顺序号（01 起，按班级已有学生递增）  
  - 示例：2025 入学、二年级 6 班（P2G）第 3 人 → **2520603**
- **不同步**：性别、生日（钉钉家校读接口不提供）；本地 `gender` 新增时暂填 `other`
- **匹配键**：优先 `students.dingtalk_user_id`，其次学号

API：`GET /api/admin/dingtalk/sync/plan`，`POST /api/admin/dingtalk/sync/apply`
